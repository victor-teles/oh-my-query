## Findings

1. **Packaged builds were already broken on `main` (1.16).** The 1.16 config copied `"dist/**/*"`, which the 1.16 CLI does not expand (`failed to copy …/dist/**/* because it doesn't exist`), and the window loaded `views://mainview/dist/index.html`. The 1.16 packaged app logs `empty response for URL: views://mainview/dist/index.html`. Fixed here: `copy: { dist: "views/mainview" }`, URL `views://mainview/index.html`, and hash history in the router (the browser-history pathname `/index.html` matched no route and rendered TanStack's "Not Found").
2. **1.16 `electrobun build` defaulted to the dev environment**, so the release workflow's `build/stable-macos-*/oh-my-query.dmg` path could not have existed. `desktop:build` now passes `--env=stable`; the release passes `--env=stable|canary`.
3. **macOS x64 and Windows arm64 release jobs ran on the wrong architecture.** Hutch does not cross-compile; the matrix now uses `macos-15-intel` and `windows-11-arm`.
4. **The devkit ships raw `.ts` that fails our strict typecheck** (109 errors, all vendor). TypeScript now reads declarations generated into `.hutch/types` (`scripts/electrobun-types.ts` tolerates only TS4000–4125 declaration-naming diagnostics inside the devkit). Probes confirmed real types: wrong RPC params/response, unknown RPC methods, and wrong `BrowserWindow`/`GlobalShortcut`/`Screen`/`Tray`/`Utils` usage all fail typecheck.
5. **Baseline bug, out of scope:** schema load fails on SQLite with `near "notnull": syntax error` on both 1.16 and 2.x.
6. Removed workarounds no longer needed in 2.x: the `as never` cast on `BrowserWindow` options and the `three` module stub.
