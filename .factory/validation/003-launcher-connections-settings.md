## Findings for the owner

1. **Plan 002 finding 1 reproduced in tooling.** CuaDriver could not focus the launcher window for foreground input ("exact target window did not become focused"). The screen was also locked, so this run cannot separate the two causes. Verify by typing after `⌥⇧Space` on an unlocked Mac.
2. **The browser suite oversubscribed Chromium locally.** With the default worker count, several animated tests failed at random with Playwright "element is not stable" (a different test each run). `vite.config.ts` now sets `maxWorkers: 4`, which matches the CI runners. Locally it is also faster: about 10 s against 22–34 s.
3. **Snapshot serializer hardened.** React `useId` values and motion's `filter`/`data-motion-pop-id` changed with test order and timing. `setup-browser.ts` now normalizes them, which rewrote `id="base-ui-_r_N_"` lines in the existing `components/ui` snapshots. Those changes are id normalization only.

## Deviations from the plan

- Activation connects first, then persists `setActiveConnection`, so a failed connect never moves the chip or the stored default.
- The shared element id is per connection (`active-connection-<id>`). With one id, the old chip and the connecting row would both mount it, and the old chip would jump to the row.
- The actions menu sits at the list's bottom-right, above the footer. Its origin is the row's trailing edge, and the list area grows while it is open, so a short filtered list never clips it.
- Field errors: the form keeps its single error line, not per-field messages. Changing that would mean rewriting the form logic, which the plan's scope excludes.
- The panel max height stays at 002's 680 pt, not 720.
- The placeholder stays "Search…" until plan 005 adds asking.
- New tokens: `--danger-ink` and `--success-ink` (AA-legible red and green text on the dark translucent panel, where `--destructive` is too dim). New `popover-material` utility.
- `lib/ai-settings*.ts` were deleted; provider metadata now lives in `packages/rpc/src/ai-providers.ts`, which `isAiConfigured` also uses.
- Redis hint copy no longer mentions the removed workspace.

## Handoff notes for plan 004

- The bun side reads keys only through `getAiSettings()` (`@oh-my-query/core`). `ai-settings-service.ts`, `ai-model.ts` and `ai-errors.ts` in `src/bun/` are the pieces to move into `packages/agent`.
- The default ask target is `AppConfig.activeConnection` (`readActiveConnection()` in `src/bun/launcher-config.ts`). The renderer's live session ids are in `ConnectionsProvider` (`state.liveIds`).
- `isAiConfigured()` in `packages/rpc` decides when the root view offers "Set up an AI provider…". Plan 005 replaces that row with the ask flow.
