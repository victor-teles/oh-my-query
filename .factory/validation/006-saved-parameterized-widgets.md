## STOP conditions

- Driver binding in read-only mode: no engine needed the fallback.
- Structural check on real proposals (OpenRouter, the configured model): four sample prompts, run several times. The first run rejected 4/4 for syntax slips (`.from` on a date, `{{limit.value}}`, a type name used as the input name, unused inputs), not for the structural check. After a worked example in the prompt and one repair round that feeds the rejection back, 3/4 are accepted per run. The remaining structural rejection was the model rewriting `5000` as `{{min}} * 100`, which the check should refuse. The check was not weakened.

## Found and fixed during validation

- The card kept the ask's title, subtitle and insight, which describe the original data. Runs now title the card with the widget name and subtitle it with the inputs of the data shown.
- The fresh-widget pulse never ran: rows mount inside `AnimatePresence initial={false}`, which skipped its declarative initial state, so `freshId` was never cleared and every later root mount reselected that widget. The pulse is now driven by `useAnimate`.
- The run view didn't take focus when opened, so ⌘K/⌘C/↵ landed on `<body>`. React only honors `autoFocus` on form controls, so the panel now focuses in an effect.
- `LauncherPanel` shares one `inputRef` between root and ask inputs, and the exiting root input clears it after the ask view mounts. `AskView` now keeps its own field ref to refocus after naming. The shared ref still affects `onShown` focus after a push (pre-existing).
- The model's defaults could disagree with the literal they replaced (50 vs 5000). `restoreDefaults` aligns template and query and restores each default from its literal.
- Widget metrics read "0 ms" because pg doesn't time queries; the service now times execution.
- Clicking a date pill opened and immediately closed its popover (focus then toggle).

## Adaptations to the plan

- Removing an input can't splice its value back into the SQL without breaking the "values are always bind parameters" rule, so a removed input becomes `fixed: true`: still bound, hidden from pills and summaries.
- A Recent row re-asks its question on its connection.
- The inputs review has a name field.
- `CardView.shape.kind` in the plan's contract doesn't exist on a union; `Widget.view` stores the card view kind (`bar | line | area | pie | kpi | table`).
- `ActionMenuItem` and the ⌘K menu were generalized (`launcher/actions/`) for the second caller; the connection menu is now a thin wrapper.
